\section{Tokenizer (R1)}
I built a byte-level BPE tokenizer with the GPT-2 pre-token rule. I first count the pre-tokens, then merge the most frequent pair repeatedly, updating the pair counts incrementally so the loop is fast. All four \texttt{train\_bpe} tests pass.

I trained it on the first 200~MB of TinyStories (allowed by the handout), with vocabulary size 10,000.

\section{Ablation (R6)}
\textbf{No warmup.} I removed warmup and kept everything else the same (lr $3\times10^{-3}$, 3,000 steps, same seed).
\begin{itemize}\itemsep0pt
\item \textbf{Measurement:} validation loss 1.926 against 1.779 with warmup: +0.147, about 8\% worse. Training did not diverge.
\item \textbf{Explanation (hypothesis, not proven):} at the start Adam has few gradients, so its scale estimate is poor, and a full-size step wastes early progress.
\end{itemize}
The gap (0.147) is much larger than the 0.012 gap in the sweep, so the direction is probably real, but I have only one seed.

\section{What went wrong (R8)}
\begin{itemize}\itemsep0pt
\item My Mac is Intel and PyTorch 2.14 has no wheel for it, so I could not install the environment locally with \texttt{uv}; I used Colab for tests and training.
\item One Colab run used a fresh copy of the starter kit instead of my code, so all tests failed with \texttt{NotImplementedError}. After uploading my own folder the tests passed.
\item \texttt{train.bin} and \texttt{val.bin} were not on Moodle (Lab~1 was after the deadline), so I had to build my own tokenizer first, which took a lot of time.

\end{itemize}
\textbf{Limitations.} The sweep has 3,000 steps and only three learning rates; all runs use one seed, so small differences are unreliable; the reference run, efficiency table, samples and some tokenizer numbers are not done or shortened; MFU is low (about 4.6\%) because the speed improvements were not done; I had very little time before the deadline.
